# CISA 2026 Minimum Elements: what is checked

`-c cisa2026` checks an SPDX 3 SBOM against the
[2026 Minimum Elements for a Software Bill of Materials (SBOM)][cisa2026].
The rules in [`cisa2026.yaml`](cisa2026.yaml) take their ids and provisions
from the [SBOM requirements ontology](https://bact.github.io/bom/req/cisa2026/);
the SPDX fields follow its
[SPDX 3.0.1 mapping](https://bact.github.io/bom/mapping/cisa2026-to-spdx30.sssom.tsv).
Outcomes are reported as for [`g7ai`](g7ai.md). SPDX 2 SBOMs are not covered:
every rule is then `not-applicable`.

## Checked

| Rule | Element | What the checker looks for |
|---|---|---|
| META-001 | SBOM Author | `createdBy` on the creation info |
| META-003 | SBOM Data Format Name | `specVersion` (a close match: the property holds the version, and its presence implies the SPDX format) |
| META-004 | SBOM Data Format Version | `specVersion` |
| META-005 | SBOM Generation Context | `software_sbomType` (a close match) |
| META-006 | SBOM Timestamp | `created` |
| META-007 | SBOM Tool Name | `createdUsing` |
| COMP-001 | Component Producer | `originatedBy` on every package |
| COMP-002 | Component Dependency Relationship | at least one `contains`, `dependsOn`, `hasStaticLink` or `hasDynamicLink` relationship in the SBOM |
| COMP-003, COMP-004 | Component Hash Value, Algorithm | `verifiedUsing` with a non-blank value on every package (a broad match) |
| COMP-005 | Component Identifiers | `software_packageUrl`, `software_contentIdentifier`, or an `externalIdentifier` of type packageUrl, cpe22, cpe23, swid, swhid, gitoid or urlScheme, on every package |
| COMP-006 | Component License | a `hasDeclaredLicense` relationship from every package |
| COMP-007 | Component Name | `name` on every package |
| COMP-008 | Component Version | `software_packageVersion` on every package |

A component rule covers the packages (AI and dataset packages included)
**reachable from the SBOM root**, the root included. The checker follows, from
the `from` element to the `to` elements, the composition and dependency
relationships (`contains`, `hasOptionalComponent`, `packagedBy`, `dependsOn`,
`hasDynamicLink`, `hasStaticLink`, `hasPrerequisite`, `hasOptionalDependency`,
`hasProvidedDependency`) and, as `reach_via` in `cisa2026.yaml` declares,
`trainedOn` and `testedOn`: a dataset that a reachable model was trained or
tested on is judged like any other component. A package that is not reachable
is not evaluated: its missing values are not reported.

## Not checked (catalogue-only)

Listed in the JSON and SARIF reports (as `out-of-scope`), never counted as
missing. The default text and HTML reports do not mention them.

| Rule | Element | Why |
|---|---|---|
| META-002 | SBOM Author Signature | SPDX 3.0.1 has only a narrow match (`verifiedUsing`); a signature cannot be told from a hash |
| META-008 | SBOM Tool Version | SPDX 3.0.1 has only a broad match (a tool's name) |
| META-009 | SBOM Version | SPDX 3.0.1 has only a broad match (a comment) |
| PP-001 to PP-006 | Practices and Processes | They describe how an organization runs SBOMs, not what an SBOM holds |

The ontology gives the Practices and Processes elements the notations
`CISA2026-PP-01` to `-06` and no SARIF rule id; `BOM-CISA2026-PP-001` to
`-006` are this checker's ids for them.

## Limits

- `verifiedUsing` holds any integrity method, so COMP-003 and COMP-004 check
  that one with a non-blank value is present. They do not check that it is a
  hash of the component itself: a package verification code or an aggregate
  hash over many files passes, though the mapping excludes aggregates from
  COMP-003.
- COMP-002 is a document-level check: the SBOM declares one of the four
  relationship types somewhere, between any two elements. A package without
  one is not reported.
- COMP-005 accepts an `urlScheme` identifier, which the mapping does not list.
- COMP-006 reads `hasDeclaredLicense` only. A package with only a
  `hasConcludedLicense` is reported missing.
- META-001 (author) is present when `createdBy` is non-empty, whatever it
  points to: a `NoAssertionElement`, or an element missing from the document,
  counts. META-007 (tool name) is stricter: a `NoAssertionElement` tool does
  not count.
- COMP-006 does not accept a `NoAssertionLicense` target (reported missing), but
  accepts a licence target that is not in the document. COMP-001 does not accept
  a `NoAssertionElement` producer, nor a producer missing from the document.
- COMP-002 does not accept `descendantOf`, which the mapping lists as a close
  match.
- META-005 reads the first root that is an SBOM element; a document with no SBOM
  element among its roots reports it missing.
- Present values are otherwise not checked for quality.
